What it does

The controls that make it your system

This is what an administrator can do without contacting us, without a consultant, and without a release.

Switch departments and tools on and off

The sidebar, the search and the permissions all follow the switches.

  • Turn whole modules on or off for your organization
  • Turn individual tools off within a module you do use
  • People only see what applies to them — no navigating past dead weight
  • Turn something on later and it appears, with the data still there

Roles you build yourself

Start from the defaults and then define exactly what a role can do, tool by tool.

  • Owner, Admin, Manager and Member to start from
  • Custom roles built from individual read / create / update / delete permissions
  • A role per real job — permit issuer, storekeeper, budget holder
  • Every member holds exactly one role per organization

Enforced server-side, not in the interface

Hiding a button is not a control, and never was.

  • Permissions evaluated by server-side security rules
  • A permission you did not grant cannot be reached by any client
  • Multi-tenant isolation between organizations
  • The audit log records who changed access, and when

Shape the organization itself

Departments, job titles and members are yours to define and change.

  • Organization profile, departments and job titles
  • Invite members by email; they join with the role you chose
  • One account can belong to several organizations, cleanly separated
  • Change structure without a migration

Branding and language

The system reads as yours, in the language each person prefers.

  • Your organization’s branding inside the workspace
  • English, French, German, Norwegian and Turkish included
  • Each member chooses their own language
  • No separate instance needed for a different site

An audit trail of the configuration

Changes to who can do what are recorded, because they matter.

  • Membership, role and permission changes recorded and attributed
  • Answers "who changed this, and when?" without guesswork
  • Useful in a client audit as well as an internal one
  • Configuration history, not just data history

Administration questions we get asked

Can we really turn off modules we do not use?
Yes — whole departments or single tools, at any time. The sidebar, the global search and the permission registry all follow the switches, so people are not navigating past features that do not apply to them.
What happens to the data if we switch a module off?
It stays. Switching a module off hides it from the interface; turning it back on later brings it back with its records intact.
How specific can a custom role be?
Down to read, create, update and delete on an individual tool. That is enough to build a role that matches a real job — a permit issuer who can sign but not configure, a storekeeper who can issue stock but not adjust it.
Is hiding a tool the same as securing it?
No, and we do not treat it that way. Permissions are enforced by server-side security rules, so a permission you did not grant cannot be reached by any client regardless of what the interface shows.
Do we need a consultant to set this up?
No. Creating the organization, choosing modules, defining roles and inviting people is a settings exercise an administrator does directly. If you want help with a large migration, ask us — but the configuration itself is yours.
Can one company run several organizations?
Yes. Groups, joint ventures and consultancies commonly do. One account can belong to several organizations and switch between them, and data never crosses the boundary between them.
